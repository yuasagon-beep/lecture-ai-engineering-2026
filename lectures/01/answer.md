# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
  - 素の Gemini では、「3レベル」を一般的な「3段階の難易度」や「理解度の段階」として捉える回答になりやすかった。講座固有の情報を知らないため、一般論にとどまる。
- 用語集の正しい意味と比べて気づいたこと：
  - LLM は講座固有の情報を知らないと、もっともらしい一般論を返してしまう。これは「ハルシネーション」や「文脈不足」の典型例であると感じたと同時に、わからないものにはちゃんとわからないと答えることができるモデルだといいと思った
- 表示できたトークン数（入力 / 出力）：
  - 実装後に確認できた例: 入力トークン数 7、合計トークン数 13。
  - 出力トークン数も `usage_metadata.response_token_count` から表示できるようにしたので、実行環境で確認可能である。

## 宿題

- 取り組んだレベル：実装 
- やったこと：
  - `app/ask.py` に Google GenAI の `usage_metadata` を使って、入力トークン数と出力トークン数を表示する処理を追加した。
  - JSON 形式で会話履歴を保存し、`--reset` と `--history-file` によって履歴を消去・保存先変更できるようにした。
  - `--chat` で対話モードを追加し、`/reset` と `/exit` で会話を再開・終了できるようにした。
- 結果：
  - 単発質問のままでも、会話履歴を使った継続質問ができるようになった。
  - 「その地名を英語にしてください」のような参照型質問で、履歴が効いていることを確認した。
- 気づき・疑問：
  - 今回、APIでモデルを呼び出すだけでは、普段使っているGeminiやChatGPTのような会話履歴の保存機能などは自　動的には備わらないことを知った。
　　また、会話を続けるほど入力トークン数が増えていくことから、過去の会話も入力に含まれていることを確認でき　　た。　会話を記憶する仕組みを自分で実装してみて、普段使っているAIサービスの裏側について少し理解が深まった
